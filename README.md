# AI問題集（ai-quiz）

高校生向けの勉強用Webアプリです。デスクトップPCのローカルLLM（Ollama）が作った問題のうち、**検証に合格した問題だけ**をストックに入れて出題します。家庭内LANのスマホから使えます。

- 今できること：
  - 数学（フェーズ1）：数学IIを中心に、数学I・Aの復習、数学B・Cを少し。20種類の小単元。レベルは高校基礎・共通テスト
  - 英語（フェーズ2）：共通テストレベルの読解（お知らせ・広告・メール／説明文／物語・体験談）と語彙（空所に入る語／文中の語の意味／スペル）
- 問題の形式：スマホ向けの選択式／キーボード入力（数学は数値・数式を sympy で同値判定、英語のスペルは英単語の完全一致）
- 解いた問題は、正誤・当時の回答・かかった時間つきで見返し、再挑戦できます
- デスクトップPCの電源が切れていても、ストックの問題を解く・見返す・採点するのは全部できます

仕様書は [docs/spec.md](docs/spec.md)、開発の引き継ぎは [CLAUDE.md](CLAUDE.md) にあります。

## しくみ

```
[スマホ / PC] ──家庭内LAN──▶ Raspberry Pi 4（NAS。常時稼働）
                               ├─ web      画面（:8000）。LLM は呼ばない
                               ├─ worker   作成依頼の処理と検証、毎日のバックアップ ──LAN──▶ デスクトップPCの Ollama
                               ├─ sandbox  答えの読み取りと sympy の同値判定（外部ネットワークなし）
                               └─ データ   NAS の HDD 上のフォルダ（quiz.db とバックアップ）
```

### 問題の作り方と検証（数学）

1. **Python（sympy）が数値・正解・誤答を作る**。誤答は「符号ミス」「公式の取り違え」などよくある間違いを実際に計算して作り、それぞれに間違いの種類の印を付けます
2. 誤答が正解とも互いとも一致しないことを sympy で確認します（見た目が同じものも重複とみなします）
3. **LLM は問題文・ヒント・解説の文章だけを書きます**
4. 問題文にテンプレートの数値・式がそのまま入っているか、解説に正解が入っているかを機械的に確認します
5. 文章の表記を機械的にそろえ（度の記号の崩れなど）、直せない崩れ（KaTeX で表示できない命令、数式の中の日本語、中国語の字、解説の途中式の計算違いなど）があれば作成役に 1 回だけ直させます
6. **検証役の LLM に、正解も選択肢も見せずに問題文だけで解かせ**、答えを sympy で正解と突き合わせます。決めた回数（初期値 2 回）すべて一致した問題だけが次に進みます
7. 検証役のモデルに解説を見直させ（辺の対応・途中式・言葉の説明）、誤りがなければストックに入ります（「状態」で切れます）

### 問題の作り方と検証（英語）

1. **読解の本文**：「本文作成役」の LLM が題名と英文の本文だけを書きます。題材はアプリの一覧から選び、同じ題材は 2 回使いません。英文に日本語が混ざっていないか・長さを機械的に確かめ（引っかかったら 1 回だけ直させます）、見直し役の LLM が時系列・因果関係・矛盾・英文の誤りを確かめます。「問題あり」なら本文ごと使いません
2. **読解の設問**：作成役の LLM が、確定した本文に 4 択の設問（正解・誤答の種類・正解の根拠になる本文の 1 文・ヒント・解説）を書きます。**根拠の文が本文にそのまま入っているか**、選択肢が重複していないか、解説が日本語かなどを機械的に確かめ、引っかかったら 1 回だけ直させます。設問が足りない本文には、次の依頼で設問を足します（本文の使い回し）
3. **本文を見せずに設問だけを解かせ**、正解できてしまった設問（常識で答えられる設問）は外します
4. **語彙・スペル**：正解の単語と誤答の単語は、アプリに入っている単語リスト（約 1200 語）から選びます。LLM は例文・和訳・ヒント・解説だけを書きます
5. **検証役の LLM に、本文・設問・選択肢を見せて（正解は見せません）解かせます**。選択肢の順番は毎回入れ替えます。決めた回数すべて正解を選んだ設問だけが次に進みます（数学と違って選択肢を見せるのは、読解の答えが文章で、選択肢なしでは突き合わせられないためです）
6. 検証役のモデルに見直させ（正解が 1 つに決まるか・英文の誤り・解説が本文と合っているか）、誤りがなければストックに入ります

同じ本文の設問は、解くときにまとめて続けて出ます。設問の一部だけが不合格になった本文は、合格した設問だけで出ます。

1 回の依頼分は「先に全問の文章を作る → まとめて検証する」の順に処理します（GPU 8GB でモデルの入れ替えを減らすため）。
デスクトップPCが止まっているときは、依頼は「Ollama を待っています」のまま残り、つながったら続きから進みます。

## 導入（Raspberry Pi に入れる）

以下のコマンドは、Pi に SSH でログインして 1 行ずつ実行します。`$` は入力しません。
**HDD のパスなど、この README に書いてある値はこの家の環境に合わせてあります。**

### 0. 事前に確認すること

- デスクトップPC の Ollama に、使うモデルがダウンロード済みであること（Windows の PowerShell で）

  ```powershell
  ollama list
  ```

  `gemma4:12b-it-qat` と `gemma4:e4b` がなければ取得します。

  ```powershell
  ollama pull gemma4:12b-it-qat
  ollama pull gemma4:e4b
  ```

- Pi の Open WebUI からデスクトップの Ollama が使えていること（LAN からの接続設定が済んでいる確認になります）
- 以前 Windows の Docker Desktop で動かしていた試運転版は不要です。止めたいときは、Windows の PowerShell で試運転版のフォルダに移動して `docker compose down` を実行します

### 1. Pi にログインする

PC のターミナル（Windows なら PowerShell）から：

```
ssh <Piのユーザー名>@<PiのIPアドレス>
```

### 2. git と Docker が使えるか確認する

```
docker compose version
```

`Docker Compose version v2.xx` と出れば OK です。`permission denied` と出たら、自分のユーザーを docker グループに入れて、ログインし直します。

```
sudo usermod -aG docker $USER
exit
```

（`exit` のあと、もう一度 `ssh <Piのユーザー名>@<PiのIPアドレス>` でログインし、`docker compose version` をやり直します）

次に git を確かめます。

```
git --version
```

`git version 2.xx` と出れば入っています。「command not found」と出たら入れます。

```
sudo apt update
sudo apt install -y git
```

### 3. GitHub から取り出すための鍵（デプロイキー）を作る

このリポジトリは非公開なので、Pi が GitHub から読み出すための鍵を作って登録します。
デプロイキーは「このリポジトリだけ」「読み取りだけ」に使える鍵です。

1. Pi で鍵を作る（質問は出ません）

   ```
   mkdir -p ~/.ssh
   chmod 700 ~/.ssh
   ssh-keygen -t ed25519 -C "ai-quiz-pi" -f ~/.ssh/ai_quiz_deploy -N ""
   ```

2. 公開鍵を表示して、出てきた 1 行（`ssh-ed25519 AAAA… ai-quiz-pi`）をまるごとコピーする

   ```
   cat ~/.ssh/ai_quiz_deploy.pub
   ```

3. ブラウザで GitHub を開き、リポジトリ `sfns50f-bit/ek9` の **Settings → Deploy keys → Add deploy key** を押す
   - Title：`raspberry-pi`
   - Key：さっきコピーした 1 行を貼り付ける
   - **Allow write access のチェックは付けない**（読み取りだけにする）
   - **Add key** を押す

4. Pi で、この鍵を GitHub に使う設定を書く

   ```
   nano ~/.ssh/config
   ```

   開いた画面に次の 5 行を貼り付け、`Ctrl+O` → `Enter` で保存、`Ctrl+X` で閉じます。

   ```
   Host github-ai-quiz
       HostName github.com
       User git
       IdentityFile ~/.ssh/ai_quiz_deploy
       IdentitiesOnly yes
   ```

   ```
   chmod 600 ~/.ssh/config
   ```

5. つながるか確かめる

   ```
   ssh -T github-ai-quiz
   ```

   初回は `Are you sure you want to continue connecting (yes/no/[fingerprint])?` と聞かれるので `yes` と入力します。
   `Hi sfns50f-bit/ek9! You've successfully authenticated, but GitHub does not provide shell access.` と出れば成功です。

### 4. リポジトリを取り出す（git clone）

```
cd ~
git clone git@github-ai-quiz:sfns50f-bit/ek9.git ai-quiz
cd ~/ai-quiz
ls
```

`docker-compose.yml` や `README.md` が見えれば成功です。以後の操作はすべて `~/ai-quiz` フォルダで行います。

### 5. データの場所を用意する（HDD 上）

1. HDD がマウントされているか確かめる

   ```
   findmnt /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c
   ```

   `TARGET` と `SOURCE`（`/dev/sda1` など）が 1 行表示されれば OK です。何も出なければ HDD がマウントされていないので、OpenMediaVault の画面で確認してください。

2. データのフォルダとバックアップのフォルダを作る

   ```
   sudo mkdir -p /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz/backups
   ```

3. 目印ファイルを置く（**これがないとアプリは起動しません**。停電後に HDD より先にアプリが起動して、空のデータで動き出すのを防ぐためです）

   ```
   sudo touch /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz/.ai-quiz-data
   ```

4. アプリ（コンテナの中の利用者番号 10001）が書き込めるようにする

   ```
   sudo chown -R 10001:10001 /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz
   ls -la /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz
   ```

   `.ai-quiz-data` と `backups` が見えれば OK です。

### 6. 設定ファイル（.env）を作る

```
cd ~/ai-quiz
cp .env.example .env
nano .env
```

`OLLAMA_BASE_URL=http://192.168.x.x:11434` の `192.168.x.x` を、デスクトップPC の固定 IP アドレスに書き換えます（Open WebUI に設定してある Ollama の URL と同じです）。
`DATA_PATH` は上で作ったフォルダになっているので、そのままで構いません。
`Ctrl+O` → `Enter` で保存、`Ctrl+X` で閉じます。`.env` は git で管理しないファイルなので、更新を取り込んでも消えません。

### 7. メモリの上限が効くか確かめる

Pi は OpenMediaVault・Open WebUI と共用なので、このアプリのコンテナにはメモリの上限（web 256MB、worker 256MB、sandbox 512MB）を付けています。

```
docker info 2>&1 | grep -i "memory limit"
```

何も出なければ OK です。`WARNING: No memory limit support` と出たら、上限が効いていません。次の手順で有効にします。

```
sudo nano /boot/firmware/cmdline.txt
```

（このファイルがなければ `sudo nano /boot/cmdline.txt`）
1 行だけのファイルなので、**行の最後に半角スペースを 1 つ空けて** `cgroup_enable=memory cgroup_memory=1` を書き足し（改行しない）、保存して Pi を再起動します。

```
sudo reboot
```

### 8. 起動する

```
cd ~/ai-quiz
docker compose up -d --build
```

初回は部品のダウンロードとビルドに 10〜20 分ほどかかります。終わったら状態を確認します。

```
docker compose ps
```

`ai-quiz-web-1`・`ai-quiz-worker-1`・`ai-quiz-sandbox-1` の 3 つが `Up`（web と sandbox は `healthy`）になれば起動しています。

```
docker stats --no-stream
```

で `MEM USAGE / LIMIT` の LIMIT が 256MiB / 512MiB になっていれば、メモリの上限も効いています。

ブラウザ（スマホでも）で `http://<PiのIPアドレス>:8000` を開きます。
右上の「状態」で、Ollama・worker・sandbox が ○ になっていることを確認してください（デスクトップPC の電源が切れていると Ollama は × ですが、問題を解くのには影響しません）。
スマホではホーム画面に追加しておくと便利です。**ルーターでポート 8000 を開放しないでください**（家庭内だけで使います）。

## 使い方

1. **問題を作る**（「作る」）：科目・範囲・レベル・形式・問題数を選んで「作成を依頼する」。順番待ちに入り、デスクトップPC の Ollama につながると順に作成・検証されます。進み具合は同じ画面に出ます
   - **範囲**：「範囲：…」を押すと単元の一覧が開きます。単元にチェックを付けると、その単元を全部選びます（複数選べます）。単元の下の「小単元」を開くと、小単元ごとにも選べます。何も選ばなければ科目全体です。単元・小単元の横の数は、まだ解いていないストックの数です
   - **レベル**：中学／高校基礎／共通テスト／入試標準。選ばなければすべて。今の数学のテンプレートと英語の小単元は高校基礎と共通テストだけです（中学・入試標準は今後追加）
   - **英語の問題数**：設問の数で数えます。読解は 1 つの本文に設問が 2〜3 問つくので、たとえば「説明文」を 6 問頼むと本文が 2 つできます（設問の一部が不合格になると、もう 1 つ本文を作ることがあり、頼んだ数より少し多くできることがあります）
   - **英語の形式**：読解と語彙は「選択式」、スペルは「キーボード入力」で頼みます
   - **選んだものは残ります**：処理中の依頼があると、この画面は 20 秒ごとに自動で読み込み直されます。範囲・レベル・形式・問題数と、変えたモデルはブラウザが覚えているので、読み込み直しても元に戻りません。モデルを「状態」の設定に戻すときは、モデルの欄の「…のモデルを初期値（状態の設定）に戻す」を押します
   - **モデル**：「モデル：作成 …（変える）」を開くと、この依頼で使う作成役と検証役（回数・別系統も）を選べます。初期値は「状態 → モデルと思考モード」の設定です。依頼したときのモデルで最後まで処理します（後で設定を変えても、その依頼は変わりません）
2. **解く**（ホーム）：科目・範囲・レベル・端末（スマホ／キーボード）・問題数（初期値 20 問）を選んで「はじめる」。範囲とレベルの選び方は「作る」と同じです。1 問ずつ表示され、答えるたびに正誤と解説が出ます。前に間違えた問題も少し混ざります。選んだ範囲の小単元からなるべく均等に選び、同じ小単元の問題が続かないように並べます
   - スマホ：選択式だけが出ます
   - キーボード：キーボード入力と選択式が出ます
   - 英語の読解：スマホでは上の「本文」「設問」のボタンで切り替えます（「設問へ」「本文を見る」のボタンもあります）。同じ本文の 2 問目からは設問から表示します。PC の広い画面では本文と設問が左右に並びます。答えた後の画面の「本文を見る」で本文をもう一度読めます
   - 英語のスペル：大文字・小文字は区別しません。ヒントは最後の文字（長い語は 2 文字目も）を教えます
3. **見返す**（「履歴」）：解いた問題の一覧。問題を開くと、当時の回答と「再挑戦する」ボタンがあります。まだ解いていない問題は（正解が見えてしまうので）開けません
4. **この問題おかしい？**：問題の下にあるボタンから報告できます。報告された問題は出題されず、記録の集計からも外れます。「状態」の画面に一覧が出るので、確認して問題なければ戻せます
5. **作成の取り消し**：「作る」または「状態」の依頼の「取り消す」で、処理中の依頼も数秒以内に止まります（「取り消し中」→「取り消し済み」）。デスクトップの GPU での生成も止まります。それまでに検証に合格した問題はストックに残ります
6. **状態**（「状態」）：上の切り替えで 5 つのページに分かれています
   - **まとめ**：Ollama・worker・sandbox の状態、ストック残数（少ないと赤くなります。ホームにも出ます）、最近の依頼、バックアップ、「おかしい？」と報告された問題
   - **モデルと思考モード**：作成・検証・見直しに使うモデルと検証役に解かせる回数、見直しをするかどうかの全体の既定値。
     - **科目ごとのモデル**：科目ごとに、役割（英語は「本文作成役」と「本文なしの確認役」も）のモデルを上書きできます。英語の「本文なしの確認役」は、本文を見せずに設問を解かせて、常識で解けてしまう設問を外す役です（設定がなければ作成役。作成役が弱いときは検証役などに変えます）。「全体の設定」のままの役割は既定値を使います。「作る」画面の初期値は、その科目の設定です。「既定値に戻す」で上書きを消せます。作成役と検証役が同じモデルだと注意が出ます（作成のときの見落としを検証でも見落としやすいため）
       - 例：英語の本文は Haiku、設問はローカルにしたいときは、英語の「本文作成役」で `anthropic/claude-haiku-5-5` を選んで「英語の設定を保存」を押します（API の設定は下の「API で作る」）
       - API の 1 日の上限：科目ごとに金額（ドル）と呼び出しの回数を決められます（0 か空なら上限なし）。今日の利用額と回数も同じ欄に出ます。上限に達した依頼は「上限に達しました」で止まります
       - 科目ごとにモデルが違うときのモデルの入れ替えを減らすため、順番待ちは同じ科目の依頼を続けて処理します
     「見直し」は、検証役の答えが全回正解と一致した問題だけ、見直し役のモデル（設定がなければ検証役のモデル）に解説の誤り（三角形の辺の対応・途中式・「上側／下側」などの説明）を探させます。正しい問題まで弾かれすぎる（「検証の成績」の「解説の見直しで誤りを指摘された」が多い）ときは「しない」にしてください。正しい問題まで弾かれすぎる（「検証役の答えが正解と一致しない」が多い）ときは、検証役を `gemma4:12b-it-qat` に変えてみてください
     - 思考モード：モデルごとに「あり／なし」を選べます。選んだ設定はモデルごとに保存されます。選んでいないモデルは「なし」です（思考ありは時間がずっとかかります。英語の 12b で 1 問約 19 分、なしは約 1.5 分）。思考に対応していないモデルはいつも「なし」で動きます。一覧には Ollama に今あるモデルだけが出ます（消したモデルの設定も残っているので、入れ直せば同じ設定が効きます）
     - 検証のテスト：わざと正解をずらした問題を流して、検証役との突き合わせで弾かれることを確かめられます（ストックには入りません）。「期待どおり検証で弾かれました」と出れば成功です。「判定できませんでした」と出たときは、もう一度流してください
   - **検証の成績**：期間（24 時間・7 日・30 日・すべて）と「この依頼番号以降だけ」で絞り込めます（直す前の古いデータを外すときに使います）。作成役のモデルごとの合格率と不合格の内訳、検証役のモデルごとの弾いた割合、**依頼ごとの比較**（作成役・検証役、合格／作成、1 問あたりの作成時間・検証時間、モデルの読み込み時間、不合格の内訳）、その期間の不合格の一覧（作成役・検証役のモデル名、問題文、生の出力）。「Markdown で表示／保存」で、この画面の表と不合格の一覧をファイルに書き出せます（Claude などのチャットに貼って相談できます）
   - **LLM の呼び出し**：最近の LLM の呼び出しごとの時間の内訳（遅いときの原因を見分けるため）
   - **問題検証モード**：下の 7
7. **問題検証モード**（「状態」→「問題検証モード」。親向け）：ストックの問題を正解つきで確かめる画面です（この版を Pi に入れる手順は「更新を取り込む」と同じです）
   - 科目・単元・レベル・作成役のモデル・状態（ストック／削除した問題／検証で不合格／表記の点検で引っかかる問題）、**作った日**（から・まで）、**管理番号**（から・まで。例：266 から）で絞り込めます。最近作った問題だけを書き出すときに使います
   - 一覧と Markdown には、問題ごとに作成日時と管理番号が出ます
   - 一覧と Markdown には、役割ごと（本文作成・作成・検証・見直し）の**思考モード**（あり／なし／API）も出ます。思考モードは依頼したときの設定で決まり、その依頼は最後までその値で作ります（後で設定を変えても変わりません）。この記録を始める前に作った問題は「記録なし」です
   - 問題ごとに、選択肢（誤答には間違いの種類）・正解・ヒント・解説・作成役と検証役のモデルが出ます
   - **削除する**：その問題は今後出題しません（回答の記録は残ります）。「削除した問題」で絞り込むと「ストックに戻す」で戻せます
   - **前に作った問題の手入れ**（「前に作った問題の手入れ」を開く）
     - 「表記をまとめて直す」：数学は度の記号の崩れ（`120^\top` など）や `\\sin` のような書き方を、英語は文字どおりの `\n` や語彙の例文の `[[ word ]]` などを、作成のときと同じ方法でまとめて直します（数式の意味は変えません。直す前の文章は各問題の「検証の記録」に残ります）。押す前に、念のためバックアップを取っておきます

       ```
       cd ~/ai-quiz
       docker compose exec worker python -m quizapp.backup
       ```

     - 「状態」で「ストックのうち表記の点検で引っかかる問題」を選ぶと、直せなかった問題が指摘つきで一覧になります。「表記の点検で引っかかる問題をまとめて削除する」で削除できます
     - 「番号を指定して削除」：内容がおかしい問題の番号（例: `8, 163, 221`）をまとめて削除します
     - 削除した分は「作る」から作成を依頼してください
   - **見直しだけをやり直す**（「見直しだけをやり直す」を開く）：上の絞り込みに当てはまる問題を、新しい順に選んだ数（最大 200 問）だけ、選んだモデルで見直させます。結果は問題の記録に足すだけで、合否は変わりません。同じ問題を別のモデル（Haiku・e4b・12b など）で見直させれば、Markdown で並べて比べられます。英語では、今の検証の判定（正解が 1 つに決まるか）と解説の見直しの両方をかけます。前に作った問題を、今の見直しで点検し直すのにも使えます。「誤りあり」と出た問題は、「状態」で「ストックのうち見直しのやり直しで誤りを指摘された問題」を選ぶと一覧になります。削除するかは、一覧で見て決めてください。「本文の見直しもする」にチェックを入れると、英語の読解では本文も 1 回ずつ見直します。進み具合は「作る」の依頼の一覧に出ます。「見直しのやり直しの比較表」を押すと、問題ごと・モデルごとに ○（問題なし）／×（誤りあり）を並べた表が出ます
   - **要確認の問題**（英語）：検証の 2 回の判定が割れた問題などは、すぐに捨てずに「要確認」になります（ストックには入らず、出題されません）。「状態」で「要確認」を選ぶと一覧になり、問題ごとに「検証 1 回目」「検証 2 回目」の判定の結果（○／×）と理由が出ます。正解が 1 つに決まる問題なら「確かめたのでストックに入れる（通す）」、おかしな問題なら理由を書いて（書かなくてもかまいません）「捨てる」を押します。「見本集で測る」の欄の「要確認を確かめた問題（通した・捨てた）を見本集の形で保存」で、確かめた問題を見本集に足す形のファイルにできます（送っていただければ見本集に足します）
   - **検証のやり方**（英語）：「状態」→「モデルと思考モード」の英語の欄で、語彙の判定（2 段階／3 段階）、読解の誤答の根拠を書かせるか（書かせない／理由を問う設問だけ／すべて）、読解の選択肢の判定の思考モードを選べます。既定は見本集でいちばん成績の良かった形（語彙は 2 段階、誤答の根拠は書かせない）です。「見本集で測る」でも選べるので、並べて比べられます
   - **英語の既定のモデル**：作成 gemma4:26b-a4b-it-qat、検証 gemma4:e4b-it-qat（2 回）、見直し gemma4:12b-it-qat です。「状態」→「モデルと思考モード」の英語の欄で何も選んでいなければ、この組み合わせになります（欄には「科目の既定」と出ます）
   - **読解の 1 対 1 の判定**（英語）：正解の根拠の近くの言葉を使った「怪しい誤答」だけ、正解と 2 つだけで比べさせ、「両方成り立つ」などと答えたら要確認にします（既定でオン。「状態」→「モデルと思考モード」の英語の欄で切り替え・しきい値の変更ができます）
   - **本文の使い回し**（英語）：同じ欄の「読解の本文の使い回し（作成）」を「使わない」にして保存すると、前に作った本文に設問を足さず、新しい本文だけで作ります（最終確認のときに使います。終わったら「前に作った本文に設問を足す」に戻してください）
   - **新しく作った問題の点検**：「状態」で「ストックと要確認」を選ぶと、合格した問題と要確認の問題をまとめて一覧・Markdown で書き出せます（要確認は判定が割れた理由も出ます）
   - **見本集で測る**（英語）：`docs/reviews/golden_set_english.json` の見本集（弾くべき問題と通すべき問題）に、選んだ検証役・見直し役で検証と見直しをかけて、「弾くべき問題を何問弾けたか」「通すべき問題を何問誤って弾いたか」を数えます。結果は依頼に残すだけで、ストックや問題の記録は変わりません。時間を短くするため、「検証で弾いた問題の見直しを省く」に初めからチェックが入っています（成績は変わりません。どの段階で拾えたかまで比べたいときだけ外してください）。進み具合は「作る」の依頼の一覧に出ます。終わったら「見本集での測定の比べる表（Markdown）」で、構成（検証役・見直し役の組み合わせ）ごとに並べて比べられます。この機能を入れた版に更新するときは、いつもどおり `git pull` のあと `docker compose up -d --build` をします（見本集のファイルを読むための設定も入ります）。その後、見本集のファイル（`docs/reviews/golden_set_english.json`）だけが新しくなったときは、Pi で `cd ~/ai-quiz` と `git pull` をするだけで読み込まれます
   - **Markdown で表示／保存**：絞り込んだ問題を、Claude などのチャットにそのまま貼れる形で書き出します。問題ごとに「検証と見直しの記録」（不合格の理由、検証役の答え、見直しの判定と確認ごとの結果、見直しのやり直しの結果）も付きます。不合格の問題は「状態」で「検証で不合格」を選んで書き出します。冒頭に「高校生向けの問題として、正確さ・分かりやすさ・難易度の適切さを評価してください。」が付きます
   - パスワード：初期はパスワードなしで入れます。子供に見られたくなければ、下の「問題検証モードにパスワードをかける」の手順で設定してください（ほかの画面にはかかりません）

### API（Anthropic の Claude）で作る（任意）

ふだんはデスクトップPC のローカル LLM（Ollama）で作り、たくさん急いで作りたいときだけ API を使う想定です。API の依頼は Ollama の依頼とは別の順番待ちで、同時に進みます（デスクトップPC の電源が切れていても作れます）。料金がかかるので、上限を決めておきます。

1. ブラウザで https://console.anthropic.com を開いてログインし、API キーを作ります（「API Keys」→「Create Key」）。表示されたキーは一度しか見られないので、コピーしておきます
2. 同じコンソールで、利用額の上限（Limits / Spend limits）も設定しておきます（アプリの上限とあわせて二重の歯止めになります）
3. Pi で設定ファイルを開く

   ```
   cd ~/ai-quiz
   nano .env
   ```

4. 次の行を探して（なければ最後に足して）、キーを書く。上限（ドル）も必要なら変える

   ```
   ANTHROPIC_API_KEY=ここにキー
   API_MONTHLY_LIMIT_USD=5
   API_JOB_LIMIT_USD=0
   ```

   `Ctrl + O` → `Enter` で保存、`Ctrl + X` で閉じます

5. 設定を反映する（この版に更新したばかりのときは、API を使うための部品を入れるので `--build` を付けて作り直します）

   ```
   docker compose up -d --build
   ```

6. 「状態 → モデルと思考モード」に「API（Anthropic）」の欄が出て、今月の利用額と上限が見られます。上限はここでも変えられます（画面の値が優先されます）

- 料金の目安（1 問あたり、作成＋検証 2 回＋見直し）：Haiku が一番安く、Sonnet はその約 20 倍、Opus は約 40 倍です。最初に数問だけ作って、「状態 → 検証の成績」の依頼ごとの比較（API の料金・1 問あたり）で実際の金額を確かめてから使ってください
- 安くするための工夫（アプリが自動でしています）：毎回同じ指示を使い回す（プロンプトキャッシュ。長い指示の作成役で効きます）、考える量を控えめにする。検証役や見直しを安いモデル（Haiku）にすると、さらに安くなります
- API や sandbox が一時的に止まっているときは、API の依頼は「待っています」になり、少し待ってから続きを進めます（料金のかかる呼び出しをすぐに繰り返しません）
- 今月の利用額が上限に達すると、API の依頼は「失敗（上限に達しました）」で止まります。上限を上げるか、翌月まで待ってください
- API を使わなくなったら、`.env` の `ANTHROPIC_API_KEY=` の後ろを空にして `docker compose up -d` を実行します

## 起動・停止

いずれも `cd ~/ai-quiz` してから実行します。

| したいこと | コマンド |
|---|---|
| 状態を見る | `docker compose ps` |
| 止める | `docker compose stop` |
| 止めたものを動かす | `docker compose start` |
| 作り直して起動（設定を変えたとき） | `docker compose up -d` |
| 完全に止めてコンテナを消す（データは消えない） | `docker compose down` |
| ログを見る | `docker compose logs --tail 50 web` （`web` を `worker` や `sandbox` に変えると、それぞれのログ） |

Pi を再起動すると、アプリも自動で起動します（`restart: unless-stopped`）。`docker compose stop` で止めたときは自動では起動しません。

### 停電のあと

停電から復帰したとき、HDD のマウントより先にアプリが起動することがあります。そのときは目印ファイルが見えないので、アプリは何も書かずに終了し、Docker が少し後に再起動します。HDD がマウントされれば自動で正常に動き出します。
しばらくしても動かないときは、ログに理由が出ています。

```
cd ~/ai-quiz
docker compose logs --tail 20 web
```

`目印ファイル .ai-quiz-data がありません` と出ていたら、「5. データの場所を用意する」の 1 で HDD がマウントされているか確認してください。

データベース（SQLite）は、書き込み途中で電源が切れても壊れにくい設定（WAL ＋ synchronous=FULL）にしています。

## 更新を取り込む

## 復元（バックアップから戻す）

   ```
   sudo cp /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz/backups/quiz-20261018-030000.db /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz/quiz.db

   ```

4. 起動する

   ```
   docker compose up -d
   docker compose ps
   ```

問題なく動いたら、`old` フォルダは消して構いません（`sudo rm -r /srv/dev-disk-by-uuid-df337903-0195-4c8c-8237-49c1f271a27c/ai-quiz/old`）。

| 症状 | 確かめること |
|---|---|
| 「状態」で Ollama が × | デスクトップPC の電源と Ollama が起動しているか。`.env` の `OLLAMA_BASE_URL` が正しいか（変えたら `docker compose up -d`） |
| 依頼が「Ollama を待っています」のまま | 上と同じ。Ollama につながれば自動で進みます |
| 依頼が「失敗」「一部完了」 | 「状態」→「検証の成績」の依頼ごとの比較と不合格の一覧で理由を見る。検証役が弾きすぎなら、モデルや回数を変える |
| API の依頼が「失敗（上限に達しました）」 | 「状態 → モデルと思考モード」の「API」で今月の利用額と上限を確かめる。上限を上げるか、翌月まで待つ |
| API の依頼が「失敗（API キーが使えません）」 | `.env` の `ANTHROPIC_API_KEY` を確かめて `docker compose up -d` |
| 依頼が「失敗」で「モデル … が Ollama に見つかりません」 | 選んだモデルがデスクトップPC の Ollama に入っていない。名前を確かめるか、`ollama pull <モデル名>` で入れてから依頼し直す |
| ストックが少ないと出る | 「作る」から作成を依頼する |
| キーボード入力で「sandbox につながりません」 | `docker compose ps` で sandbox が動いているか。止まっていれば `docker compose up -d` |
| 画面が開かない | `docker compose ps` と `docker compose logs --tail 50 web` |

## 設定（.env）

| 項目 | 既定値 | 説明 |
|---|---|---|
| `DATA_PATH` | （必須） | データの場所（HDD 上のフォルダ） |
| `WEB_PORT` | `8000` | 画面のポート |
| `OLLAMA_BASE_URL` | （必須） | デスクトップPC の Ollama の URL |
| `GEN_MODEL` | `gemma4:12b-it-qat` | 作成に使うモデルの初期値（「状態 → モデルと思考モード」の設定が優先。依頼ごとに「作る」画面でも選べる） |
| `VERIFY_MODEL` / `VERIFY_COUNT` | `gemma4:e4b` / `2` | 検証役のモデルと解かせる回数（同上） |
| `VERIFY_MODEL_2` | （空） | 別系統の検証役（1 回だけ追加で解かせる。同上） |
| `REVIEW_PASSWORD` | （空） | 問題検証モードのパスワード。空ならパスワードなし |
| `ANTHROPIC_API_KEY` | （空） | Anthropic の API キー。空なら API は使わない（worker だけに渡す） |
| `API_MONTHLY_LIMIT_USD` / `API_JOB_LIMIT_USD` | `5` / `0` | API の月の上限と 1 回の依頼の上限（ドル）。月の上限を 0 にすると API の依頼はすべて止まる。依頼の上限の 0 は「上限なし」。「状態」の画面の値が優先 |
| `ANTHROPIC_PRICES` / `ANTHROPIC_MODELS` / `ANTHROPIC_EFFORT` | （下のとおり） | 料金表（ドル／100 万トークン）・選べるモデル・考える量（`.env.example` を参照） |
| `MAX_ATTEMPTS` | `3` | 1 問あたり何回まで作り直すか |
| `OLLAMA_RETRY_SECONDS` | `60` | Ollama につながらないときの再試行の間隔（秒） |
| `BACKUP_KEEP` / `BACKUP_INTERVAL_HOURS` | `14` / `24` | バックアップの世代数と間隔 |
| `LOW_STOCK` | `40` | 科目・端末ごとのストックがこれ未満で「少ない」と表示 |
| `RETRY_PERCENT` | `30` | 解き始めのセットに混ぜる「間違えた問題」の上限（%） |

## 開発者向け

テストの実行（Python 3.12 以上）：

```
python -m venv .venv
.venv/bin/pip install -r app/requirements.txt pytest
.venv/bin/python -m pytest
```

将来ミニPC（x86）へ移すときは、同じ手順（`git clone` → データのフォルダを移す → `.env` の `DATA_PATH` を直す → `docker compose up -d --build`）で動きます。イメージはその場でビルドするので、arm64 / x86 の違いは気にしなくて構いません。
