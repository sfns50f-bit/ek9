- **英語の残り**（第 11 回の 2 章。**3 つとも直した**。docs/english.md の 5-10 章）：
  1. 「語の直前に a / an がない」の点検を、文中の語の意味の問題から外す（作成役が冠詞を消して英文を誤らせた。#1215）
  2. 機械的な点検で落ちる問題を捨てずに直す（不合格の理由で一番多い 30 問）：誤答の種類「本文に書かれていない」の付け替え、ヒントの「第 N 段落」をコードで直す、解説の A・B の記号を選択肢の文に置き換える、空の解説だけを書き直させる

- **次の科目で流用できる仕組み**（どれも科目によらない。CLAUDE.md の「作成と検証の流れ」）
  - **見本集とその測定**（`golden.py`、`jobs.kind = "golden"`）：`docs/reviews/golden_set_<科目>.json` に弾くべき／通すべき／微妙の問題を置けば、問題検証モードの「見本集で測る」で検証役・見直し役・検証のやり方の構成ごとに、要確認を公開しない扱いの成績・所要時間・理由を比べられる。人が確かめた要確認の問題を見本集の形で書き出して足していける
  - **選択肢ごとの判定・正解を抜いた判定・1 対 1 の判定**：解かせて答えを突き合わせるより、正解が 1 つに決まるかを確かめるほうが、正解が 2 つある問題を拾えた（英語の `verify`。公共など選択式の科目でそのまま使える考え方）
  - **要確認**（`needs_check`、`Subject.verify_split_check`）：判定が割れた問題は捨てずに公開もせず、人が通す・捨てるを選ぶ。一覧に検証の回ごとの判定の理由が出る
  - **科目ごと・役割ごとのモデルと思考モード**：`Subject.default_models` / `default_think` / `model_roles`、「状態 → モデルと思考モード」の科目ごとの欄、依頼ごとの記録（`jobs.think` / `jobs.options`）。検証のやり方の切り替え（`Subject.verify_options`）で、新しい方式を今の方式と並べて測れる
  - **進め方**：実機で作る → 開発者が AI に書き出しを点検させる（docs/reviews/）→ 見本集に足す → 直す → 見本集で測る、の繰り返しで、10 回のレビューで締めた

## 3. 仕組みの要点（次のフェーズで触るところ）

- **3 つのコンテナ**：web（画面。LLM・sympy・anthropic を読み込まない）、worker（作成・検証・バックアップ。Ollama と API の 2 つの順番待ちを別スレッドで同時に処理）、sandbox（答えの文字列の読み取りと sympy の同値判定。外部ネットワークなし）
- **科目は差し替え式**：`app/quizapp/subjects/base.py` の `Subject`（`units` / `generate` / `verify` / `review` / `grade`）を実装して `subjects/__init__.py` の `REGISTRY` に 1 行足す。中心部分（worker / web / stock / db）は触らない（CLAUDE.md のルール 3）
- **本文つきの科目の入口は用意済み**：`Draft.passage`（dict）を返せば worker が `passages` 表に保存して問題と結び付ける。1 つの本文に複数の設問は、同じ dict を持つ `Draft` のリストを返す。検証役は `problem.passage` を読める。解く画面（`play.html`）は本文の表示の入口だけある
- **LLM の出力**：JSON スキーマを使わず、`[[項目名]]` の見出しで区切った平文（`llm.tagged_instructions` / `parse_tagged`）。スキーマの `properties` に `description` を書けば、その名前で出力させる
- **文章の確認の流れ**（数学）：表記をそろえる（`latexfix.normalize`）→ 点検（`textcheck` の式・値・正解、`latexfix.problems`、解説の途中式）→ 落ちたら 1 回だけ直させる → 検証役が問題文だけで解く（設定回数すべて一致）→ 解説の見直し（LLM）→ ストック
- **モデルの指定**：依頼ごとに `jobs` に保存（`runtime.plan_for_job`）。`anthropic/…` で始まれば API。上限は「状態 → モデルと思考モード」

### 気をつけること

- **sandbox の同時実行は 1**：2 つの順番待ちと子供の採点で共有している。込むと待ちが長くなり、その依頼は「待っています」になる。
- **worker のメモリは約 127MB**（上限 256MB）。英語で本文を扱うと増えるので確かめる。
- **プロンプトキャッシュは作成役だけで効く**：512 トークン以上の前置きが要るため。API のモデルが考えている間は、取り消しが少し遅れることがある。
- **params の形を変えると重複の判定が 1 回だけすり抜ける**：テンプレートの `params` の形を変えると `params_key` が変わる。前のストックと同じ数値の問題が 1 回だけ入りうる。
