## 0. 要約

- 2段階化（本文 → 設問）と本文の使い回しは正しく動いている。第3回で先に入れたプロンプトのルール（the writer、人名の英語表記、example.org）も効いている
- モデル比較の結論：**英語の作成役は gemma4:12b 思考なし**にする
  - 12b 思考なし：1問約1.5分。20問中、問題は2問
  - 12b 思考あり：1問約19分。質の差ははっきりしない
  - 26b-a4b 思考なし：約1分と速いが、読解9問中3問に問題（うち1問は致命的）
  - e2b：合格率12%。英語では使わない
- 残っている問題の多くは**モデルではなく点検・プロンプトの穴**（選択肢の記号の呼び方、「入らない語」の漏れ、正解の裏付けの確認不足）
- 検証役はほとんど弾いていない（e4b は110問中3問、Haiku・bonsai は0問）。品質を上げるには**見直しを強くする**方が効く

## 2. 修正依頼

手を付ける順番：**A → B → 1章の設定 → C → D → E**。A と B はプロンプトと正規表現の修正が中心。

### A. 機械的な点検（`check.py` ほか）

| # | 内容 | 該当 |
|---|---|---|
| A-1 | **選択肢を記号で呼んでいないかの点検を広げる**。今の点検は「A 選択肢」「C の」の形を拾えていない。`[A-DＡ-Ｄ]\s*(の|は|が|を|選択肢)`、`選択肢\s*[A-DＡ-Ｄ]` などを追加。解説・ヒントの両方 | #758, #548, #547 |
| A-2 | **アプリ内部の言葉を全出力で禁止**：「入らない語」「与えられた」「指示」「要点に従」など。スペル問題（`en-spelling`）には誤答の語をそもそも渡さない | #619, #621, #622, #623, #629, #631, #632, #638, #524, #732, #697, #682, #485 |
| A-3 | **URL・メールのドメインは `example.com` / `example.org` / `example.net` とそのサブドメインだけ許可**。`greenleafcafe-example.org` のようにハイフンでつないだ形は不合格（ドメイン部分を正規表現で厳密に判定） | #652, #490 |
| A-4 | ヒントと解説の1文目が同じ（またはほぼ同じ）なら弾く。ヒントに根拠の文がそのまま入っている場合、ヒントに正解語の日本語の意味（`words.py` の意味欄）が入っている場合も弾く | #758, #503 |
| A-5 | ヒントの「第N段落」を、根拠の文が実際にある段落番号と照合する（コードで段落番号が分かるため） | #615 |
| A-6 | 本文の根拠の文が内側の引用符で終わるとき、閉じの `"` が消える不具合を直す（例：`…"cup of tea.”`） | #607, #581 |
| A-7 | 語彙の意味の問題（`en-vocab-meaning`）の解説・ヒントに「空所」「入る」「入れる」がないか | #497 |
| A-8 | 本文なしの確認（`_blind_check`）は作成役のモデルで行っているため、作成役が弱いと効かない。12b なら問題ないはずだが、作成役を変えたときのために検証役か見直し役のモデルでも行えるようにしておく | #548 |

### B. 設問作成のプロンプト（`prompts.py`）

| # | 内容 | 該当 |
|---|---|---|
| B-1 | **解説の最初に、正解の理由を根拠の文とともに書く**。そのあとで誤答を説明する。誤答の説明から始めない | #782, #783, #784 |
| B-2 | **正解の選択肢には本文にない要素を足さない**。特に because・more・only・all などの因果・比較・限定の言葉を、本文にないのに入れない | #495, #522, #684, #691 |
| B-3 | 理由・目的を問う設問では、根拠の文も理由・目的を述べた文にする（結果を述べた文は使わない）。本文に理由が書かれていなければ、その設問は作らない | #761 |
| B-4 | 語彙の例文は、単独で読んで理由と結果が常識的につながる内容にする | #775, #485, #697, #524 |

### C. 見直し（`review`）の観点を追加（第3回 3章 D の再掲＋追加）

1. **正解の選択肢の各要素が根拠の文で裏付けられているか**（本文にない要素や因果が混ざっていないか） → #495, #522, #584, #684, #691
2. **各誤答を文に入れても成り立たないか**（空所補充で正解が2つ以上にならないか） → #536, #599
3. 誤答のラベルと、その誤答の内容・解説の説明が一致しているか。一致しなければ正しいラベルに置き換える → #516, #585, #600, #685
4. 例文・本文の筋が通っているか（時系列・因果・矛盾） → #775, #570, #571
5. 解説の主語・目的語が本文と一致しているか（誰が誰に何をしたか） → #492
6. 本文の見直しでは「言葉と内容の食い違い」も見る（例：mythical civilization の遺物を本物の出土品として展示） → #570, #571
