## 1. 最後の修正：怪しい誤答だけ、正解と1対1で比べる（読解）

### 1-1. 対象の誤答を選ぶ（機械的）

- 読解の各設問で、誤答ごとに「**根拠の文と、その前後1文**」と、誤答の内容語（冠詞・前置詞・代名詞などを除いた語）の重なりを数える
- 重なりが多い誤答（例：誤答の内容語の半分以上が根拠の文と前後1文にある）を「怪しい誤答」とする。しきい値は設定で変えられるようにする
- **言葉の重なりは「どの誤答を確かめるか」を選ぶためだけに使い、これだけで止めない**（07 の D が失敗した理由）

### 1-2. 1対1の判定（検証役のモデル）

- 怪しい誤答ごとに、本文・設問と、**正解とその誤答の2つだけ**を見せる（並べる順番は毎回入れ替える）
- 問い：「設問への答えとして、本文に照らして成り立つのはどちらか。両方成り立つなら『両方』と答える」
- 答えは「1／2／両方」のどれかと、理由1行に固定する
- 「両方」または誤答の方を選んだら**要確認**にする。読めなければ1回だけ聞き直し、それでも読めなければ要確認
- 2回の検証のうち1回目だけで行ってよい（時間を抑えるため）。1問あたりの所要時間を記録する
- 設定で切り替えられるようにする（既定はオン）

### 1-3. テスト

- テスト用の LLM で、#860・#796 の形（同じ段落の内容を使った誤答）が要確認になること、#605 のような通すべき問題が止まらないことを確かめる

## 3. 最終確認

### 3-1. 見本集

| # | 設定 |
|---|---|
| 1 | 既定（#130 と同じ）＋1章の1対1の判定 |
| 2 | 1と同じ設定をもう一度（回による結果の揺れを見るため） |

**合格の条件**
- 要確認を公開しない扱いで、弾くべき28問を**2回とも28問止める**（少なくとも27問以上。止まらなかった問題がある場合は理由を記録する）
- 通すべき16問のうち止めたのが**2回とも2問以下**

### 3-2. 実際の問題作成（最終想定の設定）

既定の設定（作成 26b／検証 e4b ×2／見直し 12b＋1章の1対1の判定）で、次を作る。

| 小単元 | 数 |
|---|---|
| 読解（お知らせ・説明文・物語を合わせて、本文4〜5本） | 設問15問 |
| 語彙：空所に入る語 | 10問 |
| 語彙：文中の語の意味 | 10問 |
| 語彙：スペル | 10問 |

- **本文の在庫は使わず、新しく作った本文だけで作る**（古い本文の影響を除くため）
- 書き出すもの
  1. 合格した問題（problems の .md、検証と見直しの記録つき）
  2. 要確認の問題（どの判定で割れたかと理由つき）
  3. 検証の成績（quality.md）：合格・要確認・不合格の割合と理由の内訳、1問あたりの所要時間

**合格の条件**
- 合格した問題を人（とレビュー）が確認して、**致命的な欠陥が0問**
- 合格率（合格÷作った下書き）が**50%以上**（低すぎると作成に時間がかかりすぎるため）
- 要確認の割合が**作った下書きの15%以下**（多すぎると人の確認が追いつかないため）

## 4. 英語の締め

最終確認で合格の条件を満たしたら、次を行って英語の開発を締める。

1. **既定の設定を確定する**（1章を含む）。効果のなかった設定（3段階、D、読解の思考あり）は、切り替えだけ残して既定はオフ
2. **`docs/english.md` を最新にする**：作り方、検証の流れ（選択肢ごとの判定、正解を抜いた判定、スペルの別解、1対1の判定、例文の筋の確認、本文なしの確認）、見直し、既定の設定、見本集の使い方
3. **分かっている限界を `docs/english.md` に書く**
   - 読解の「誤答も本文で裏付けられる」型は、1対1の判定でも完全には防げない可能性がある
   - 例文の筋の破綻（#775 のような、理由と結果のずれ）は、見直しで拾えないことがある
   - 検証役が e4b のとき、境界の問題（#987 のような副詞）で止めすぎることがある
4. **見本集を続けて使えるようにする**：要確認の一覧から人が判断した問題を、見本集に足せる流れを手順として書く（07 の B で作った機能）
5. **引き継ぎメモ（`docs/handover.md`）を更新する**：英語の完了、次のフェーズ（公共など）で流用できる仕組み（見本集、選択肢ごとの判定、要確認の扱い）

最終確認で条件を満たさなかった場合は、何が足りなかったかを書き出して、次回のレビューで判断する。
