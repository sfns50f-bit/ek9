# 数学の作り方の詳細（数学だけで使う決めごと）

数学の問題を直すときは、このファイルだけ見れば分かるようにしてある。
アプリ全体のルール・構成・科目によらない決めごとは [CLAUDE.md](../CLAUDE.md)、経緯の要約は [handover.md](handover.md) にある。
開発者が AI に点検させた生成問題のレビュー結果（原文）は [第 1 回](quiz-review-findings.md)・[第 2 回](quiz-review-findings-2.md)。

## 1. 部品の場所

| ファイル | 役割 |
|---|---|
| `app/quizapp/subjects/math/__init__.py` | `MathSubject`（`generate` / `verify` / `review` / `grade`）。作成 → 文章の確認 → 直しの依頼、検証役の答えの突き合わせ、解説の見直し、弧度法の扱い（`_same_angle_in_radians`） |
| `app/quizapp/subjects/math/templates.py` | 20 テンプレート（sympy）。`@template(...)` に小単元 ID・単元・名前・レベル・関連する単元。`triangle_givens()`、1 次の因数の書き方 `xf(r)` |
| `app/quizapp/subjects/math/catalog.py` | 単元（`UNITS`）と間違いの種類（`MISTAKES`）。`templates.py` の `@template` を **ast で読む** `template_info()`（sympy なし。web が使う） |
| `app/quizapp/subjects/math/prompts.py` | 作成役・直し・検証役・解説の見直しのプロンプト |
| `app/quizapp/textcheck.py` | 問題文にテンプレートの式・値が、解説に正解が「そのまま」入っているかの確認（LaTeX の揺れだけ吸収） |
| `app/quizapp/latexfix.py` | LLM が書いた文章の表記の直し（`normalize`）と崩れの点検（`problems` / `question_problems`）。sympy なし |
| `sandbox/sandbox_service/mathcheck.py` | 答えの文字列の読み取り（`preprocess`）と sympy の同値判定、解説の「=」の確認（`equalities`） |

- `textcheck` と `latexfix` は `app/quizapp/` の直下にあるが、**中身は数学向け**（LaTeX・度の記号・数式）。英語などほかの科目にそのまま当てはめない
- 問題検証モードの「表記の点検で引っかかる問題」（`review.text_issues`）は、今は科目を見ずに `latexfix` をかける。英語の問題が入ったら、科目ごとの点検に分ける必要がある

## 2. 基本の決めごと

- **数値・正解・誤答は Python（sympy）で作る**。LLM が書くのは問題文・解説・ヒントだけ
- 誤答には `catalog.MISTAKES` の印（符号ミス・公式の取り違えなど）を付ける。誤答どうし・正解と重ならないことを sympy で確かめる
- **ありえない誤答を出さない**：テンプレートの `valid`（確率は 0〜1、長さ・面積は正）に合わない誤答は選択肢に使わない
- 範囲：子供は高校2年。数学II（三角関数・指数対数・微分積分・式と証明）中心に 12、数学I 4、数学A 2、数学B（数列）1、数学C（ベクトル）1 の計 20 小単元
- 難易度の選択はなく、テンプレート（小単元）ごとにレベルが決まる（`base.LEVELS`：jhs 中学／basic 高校基礎／common 共通テスト／exam 入試標準）。今は高校基礎 10・共通テスト 10。中学・入試標準は今後追加
  - 反復試行と解と係数の関係は公式 1 回の適用なので「高校基礎」
- 関連する単元：テンプレートの `related=(...)` を `problems.related_units` に写す（複数の単元を組み合わせた問題を後で作るため。今は記録だけ）
- 同じ数値の重複：テンプレートと `params_key` が同じ問題がストックにあれば入れない（`duplicate`）。**`params` の形を変えると、前のストックと同じ数値の問題が 1 回だけ入りうる**（反復試行・2倍角・対数の値・面積・組合せで実際に起きた。問題検証モードで見つけたら削除）
  - 組合せは言い方（人・本・玉）を params から外し、同じ n・r は同じ問題とみなす

## 3. テンプレートごとの注意

- **図形と計量（余弦定理・面積）**：問題文の辺の値は `CA = …` `AB = …` の形だけ認める（`triangle_givens`）。b・c と書かせると「辺 AB の長さ b」のように取り違えるため。角は ∠BAC・度の記号なし・弧度法などの書き方の候補を認める。辺は 2〜12
- **ベクトルのなす角**：正解の角を 30・45・60・90・120・135・150° から同じ確率で選ぶ。成分は √3 を含む向き（大きさ 2・4・6）と、-5〜5 の整数の組。前は 45°/135° しか出ない、30° に偏る、という指摘があった
- **度の答え**（answer の latex が `^\circ` で終わる）：同じ角の弧度法（`pi/6` など）も正解とみなす。検証と、子供のキーボード入力の採点の両方。web でも使うので、sympy なしで弧度法の式を作る
- **1 次の因数**：`templates.xf(r)` で書く（r = 0 なら `x`。`(x + 0)` を出さない）
- **反復試行**：硬貨・玉・さいころの目の種類、n 回とも。「起きること」（1の目・表・赤玉）も givens に入れて問題文にあるか確かめる
- **2倍角**：cos θ を与える型、tan 2θ、ピタゴラス数。問題文に入れる値を givens から読み直して角と比べる
- **解と係数の関係**：解が虚数のとき α²+β² が負になってもおかしくないことを解説で触れさせる
- **2次不等式**：≦・≧ も。答えが範囲の問題で、問題の不等式を書き写しただけの答え（x^2-2x-3>=0）を正解にしない（`mathcheck._check_range_form`：不等号の両側が文字だけか数だけ）
- 数値の範囲（第二弾で広げた）：組合せ 5〜15 から 2〜5、弧度法は負の角も、合成は係数の組 200 通り、対数は底 7・真数 1/b、対数方程式は底 5、面積は x² の係数 1〜3・負も

## 4. 1 問の作り方の流れ

1. テンプレートで数値・正解・誤答・解き方の要点（`steps`）を作る
2. 作成役が問題文・ヒント・解説を書く（`[[question]]` `[[hint]]` `[[explanation]]` の見出しの平文。理由は CLAUDE.md の「LLM の出力」）
3. 表記の機械的な直し（`latexfix.normalize`）
4. 文章の確認。落ちたら同じ数値のまま**指摘した点だけ**を 1 回直させる（`FIX_ROUNDS = 1`。作り直しの回数は使わない）。それでもだめなら不合格
   - `textcheck`：問題文にテンプレートの式・値（`text_givens`）、解説に正解（`explanation`）。問題文・ヒントに正解が書かれていたら `answer_leak`
   - `latexfix.problems`：表記の崩れ（`text_format`）
   - sandbox の `equalities`：解説の数どうしの「=」（`explanation_math`）
5. 検証役が問題文だけで解く（正解も選択肢も見せない）。設定回数すべてで正解と一致したら合格
6. 解説の見直し（LLM。設定で切れる）
7. ストックへ

### 文章の確認の細かいところ

- `textcheck.normalize`：度の記号の揺れ（°・^\circ・\circ・^o・º・˚・∘・度・\degree）と「∠」、√ と分数の書き方（2√21、2√(21)、2\sqrt{21}、\frac{3}{5} と 3/5）をそろえる。数字の途中での一致は数えない。三角関数の値の式は括弧つきの書き方も認める
- 解説に正解が見つからなければ、解説の数式を sympy で正解と比べる（`_explanation_has_value`）
- 値の書き換えは数字で確かめ、辺や角の取り違えは検証役が気づく

## 5. 表記の直しと点検（latexfix）

原因の経緯：前は Ollama の format（JSON スキーマ）で出力させていたため、バックスラッシュの後ろが `" \ / b f n r t u` に縛られ、`\circ` が `\top`・`\theta`・`\rho`・`°` に、`\angle` が `ngle` に押し曲げられていた（第 1 回のレビュー）。見出しの平文に変えて根本は直った。以下は残りの揺れの対策。

### 直し（`normalize`。作成のたびと、問題検証モードの「表記をまとめて直す」）

- 数字のあとの度の記号の揺れ → `^\circ`（数式の外は °）。`^\theta` `^\rho` `^\times` `^o` を度とみなすのは、角度の話（角・∠・°・△ など）のときだけ（`2^\theta` などの本当の指数を変えない）
- `\\` → `\`：後ろが KaTeX の命令のときだけ（`\begin{cases}` の改行 `\\` は変えない）
- 文字どおりの `\n` → 改行：後ろが英字でないときだけ（`\neq` `\nearrow` は変えない）
- `\uXXXX` → その文字。制御文字になったもの → 元の命令。`\ngle` → `\angle`
- 意味の変わらない簡体字を日本語の字に（计→計 など。「据」は日本語でも使うので変えない）
- $ で囲まれていない `\begin{align*}` などを `$$\begin{aligned}…\end{aligned}$$` に（KaTeX は文中の align を表示できないので、数式の中の align も aligned に）
- 「答え: 8/3」のように $ のない答えの行を `$…$` で囲む（同じ行だけ。`%` と `*` を含むものは囲まない。度の記号の直しより先に囲む。2 回かけても同じ結果）

### 点検（`problems`。落ちたら直しを頼む）

- 制御文字、`¶`、バックスラッシュの抜け（`rac{` `egin{`）
- $ の数が奇数・`\$`。`$$…$$`・`\(…\)`・`\[…\]` も数式として扱う
- 数式の中の改行・日本語（`\text{}` の中は可）、{} の対応、`\frac` の引数の数
- KaTeX にない命令：アプリに同梱の katex.min.js から命令の一覧を作る（`katex_commands`）。KaTeX そのものは Python で動かせないため
- 数式の外の LaTeX の命令（`\int` など）、中身のない数式（`$°$`）
- 中国語の簡体字（日本語の文字コード cp932 にない漢字）
- 選択式なのに「示せ」「説明せよ」「過程」、問題文の文末が「求める。」
- 解説が短すぎる（40 字未満）
- `(x + 0)` のような 1 次の因数の不要な項（`8 - 0 = 8` のような計算の途中は弾かない）
- 作成の指示や「解き方の要点」への言及
- 誤った用語（2 点形の式・微分方程式・無理数を払う・二乗差の積分）

### 解説の「=」の確認（sandbox の `equalities`）

- 解説の数どうしの「=」が等しいか確かめる。度・対数・組合せ・添え字・不等号などを含む式は誤判定しやすいので確かめない
- sandbox の不調でできなかったときはログに出し、それだけで不合格にしない

## 6. 検証役の答えの読み取り（主に sandbox の `mathcheck`）

- `preprocess`：LaTeX（`\frac` `\dfrac` `\sqrt` `\boxed` `\leq` `^{\circ}` `\pi` など）、桁区切り（1,140。1 つの数の答えのときだけ）、全角、「答えは〜です」「よって」などの書き添え、Markdown の太字
- answer 欄が読めないとき（「@35/4」など）の救済（`subjects/math/__init__.py` の `_answer_candidates`）：answer の 1 行目、work の `\boxed{…}`、「答え: …」の行、work の最後の「=」の行（行全体と、最後の「=」の右側）。読めた最初のものを使う
- **日本語などが残った答えは読み取りエラー**（文字の積として読んで「数値が違う」になるのを防ぐ）
- 正解にない関数名を使った答え（「sin(5π/6)」「binomial(10,3)」のような書き写し）は読み取りエラー（`_check_functions`）。採点でも同じ
- 不合格の理由は「答えが読み取れなかった（solver_unreadable）」と「答えは読めたが数値が違う（solver_mismatch）」に分ける

## 7. プロンプト（`prompts.py`）

### 作成役

- 日本語の入った値（「10人」「3回」）は $ の外に書く（前は `$3回$` が量産された）。度は `^\circ`。数式は必ず $ で囲む。複数行は aligned
- 数式の中に日本語を入れない、中国語を混ぜない
- 問題文は「〜を求めよ。」で終える。短く（前置き・言い直しなし）
- 解説は途中式を省かない。言葉の説明を式と合わせる。ヒントを解き方に合わせる
- 作成の指示や解き方の要点そのものに触れない
- 教科書の用語を使う（点と傾きの式・底の変換公式・分母の有理化など）
- 入力の例（`input_hint`）と検証役のプロンプトの例に**具体的な値を書かない**（文字 a/b などだけ。答えが見えるのを防ぐ）

### 解説の見直し役（`explanation_review`）

- 検証役が全回一致した問題だけ、検証役のモデルに 1 回見させる。「問題あり」なら不合格。結果が読めないときはそれだけで不合格にしない。判定は 1 行目が「問題なし／問題あり」で始まるかで見る
- 見るところ：辺の対応（a=BC, b=CA, c=AB）、途中式、言葉の説明（上側/下側など）と直後の式の矛盾、ヒントと解き方の一致、問題文の言い直し、日本語として自然か
- **教科書でよく使う書き方（`\log_2 (x-4)(x-6)` の括弧の省略など）は誤りとしない**（#269・#275 の弾きすぎ）
- 初期は「する」。「状態 → モデルと思考モード」と「作る」画面で切れる。正しい問題まで弾きすぎるようなら切る。検証のテストではしない

## 8. 検証のテスト（正解をずらす）

- /status から「正解を +1 ずらした問題」を流せる（ストックに入らない）。**検証役との突き合わせ（solver_mismatch など）で弾かれたときだけ成功**
- 文章の確認など手前で落ちたら 3 回まで作り直し、届かなければ「判定できませんでした」
- テストのときは、LLM に解き方の要点（本当の正解を含む）を渡さない。途中式の確認・解説の長さの確認・解説の見直しもしない（検証より前に落ちてしまうため）
- 全 20 テンプレートで弾かれることを自動テストで確かめている（`test_tampered_answer_for_every_template_is_rejected`）

## 9. テンプレート（小単元）を足す手順

1. `app/quizapp/subjects/math/templates.py` に関数を 1 つ書き、`@template("小単元ID", unit="単元ID", label="画面に出す名前", level="basic" など, related=("関係する単元ID",))` を付ける。`@template` の引数は文字列・タプルをそのまま書く（web は sympy を読まずに ast でこの引数を読むので、変数や式は使えない）。単元が新しければ `catalog.UNITS` に 1 行足す
   - `Instance` の `givens`（問題文にそのまま入る式・値。書き方の候補はリストで）、`answer`（sympy）、`candidates`（誤答と `catalog.MISTAKES` の印。4 つ以上あると安心）、`steps`、`params`（同じ数値の重複の判定と、テストの確認に使う）、`input_hint`（**具体的な値を書かない**）、`valid`（ありえない誤答を外す条件）
   - 1 次の因数は `xf(r)`、三角形の辺・角は `triangle_givens()` を使う
2. `tests/test_math_templates.py` の `CHECKS` に、**別の計算方法での確認**を 1 つ足す（`test_every_template_has_an_independent_check` が足りないと落ちる）
3. `python -m pytest` を実行する。単元・レベルの値が正しいか、web が読む情報と一致するか（`test_template_info_is_read_without_sympy`）、誤答が重ならないか、正解をずらすと検証で弾かれるか（`test_tampered_answer_for_every_template_is_rejected`）まで自動で確かめる。画面（範囲・レベルの選択、ストック数）には自動で出る

## 10. 関係するテスト

- `tests/test_math_templates.py`：20 テンプレートの正解を別の方法で確認、誤答の重複なし、キーボード入力での採点
- `tests/test_latexfix.py`：度の記号の揺れ（実際に見つかった 16 通り）を直す、本当の指数や `\neq` は変えない、表記の崩れの指摘。実際のレビューで見つかった崩れの例が入っているので、直し方を変えたらここで確かめる
- `tests/test_worker.py`：正解をずらした問題が弾かれる、文章の確認と直しの依頼、解説の見直し、度の答えを弧度法で答えても正解（`test_degree_answer_given_in_radians_is_accepted`）
- テストの LLM（`tests/conftest.py::OracleLLM`）は、作成役は式をそのまま書き写し、検証役は seed からテンプレートを作り直して本当の正解を答える

## 11. 実機とレビューの記録

### 実機の結果

- 初回（gemma4:12b 作成・e4b 検証）：36 問中 10 問合格。図形と計量が `text_givens` で全滅（「∠BAC = 30°」「角A は 30度」と書くため）→ 書き方の候補を認めた
- 別系統の検証役 qwen2.5:7b は正しい問題まで弾きすぎた（不等式で境目の値だけを答えるなど、20 問中 11 問）。e4b は 9% → 別系統の検証役は「使わない」を推奨
- 第一弾のあと：作成 30 問で不合格 8 回。ほとんどが「検証役の答えが読み取れなかった」→ work の最後の「=」の行からの救済を入れた。同じ内訳が多ければ、検証役のプロンプトで answer 欄の書き方をもっと強く指定する
- 修正後：70 問中 60 問合格（86%）→ 20 問中 19 問。API（Haiku）で 20 問 0.03 ドル
- 不合格の一覧から：ベクトルのなす角を弧度法で答えていた → 弧度法も正解に。中国語の字（计）→ 直しに追加。`\log_2 (x-4)(x-6)` を見直し役が弾いた → 誤りとしないように

### 生成問題のレビュー（開発者が AI に点検させた結果）

- [第 1 回](quiz-review-findings.md)（#1〜#244、97 問）：数値はすべて正しい。LaTeX の崩れ（特に度の記号）、内容の誤り数件、ありえない誤答 → 見出しの平文、`latexfix`、`equalities`、解説の見直し、`valid`、`triangle_givens` の `CA =` `AB =`
- [第 2 回](quiz-review-findings-2.md)（#266〜#335、60 問）：数値はすべて正しい。表記の崩れはほぼ解消。用語の誤り、指示への言及、$ の抜け、`(x + 0)`、ベクトルのなす角の偏り → 点検の追加、プロンプト、`xf`、角を均等に

### 前に作った問題の手入れ（開発者の作業）

- 問題検証モード →「前に作った問題の手入れ」：表記をまとめて直す（直す前の文章は各問題の記録に残る。先にバックアップを取る。手順は README）、「表記の点検で引っかかる問題」の一覧、まとめて削除、番号を指定して削除
- 内容の誤りがあった問題（#8・#163・#221・#226・#229・#237・#238・#241 など）と、第 2 回の 6 章の古い問題（#210・#218・#226 など）は番号で削除して作り直す
- 書き出しは「作った日」「管理番号」で絞れる（修正前の問題と見分けるため）

## 12. しなかったこと・次の候補

- **問題文の条件をコードで差し込む形**（LLM に地の文だけを書かせる）：見出しの平文で式が書いたまま届くようになり、`textcheck` と直しの依頼で足りると判断した。問題文の式の崩れが残るようなら検討する
- 中学レベル・入試標準のテンプレート、複数の単元を組み合わせたテンプレート（`related`）。手順は 9 章
