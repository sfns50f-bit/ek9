## 2. LaTeX 表記崩れ

### 2-1. 度記号（最多・最優先）
問題文の角度が `^\circ` 以外になっている。種類がバラバラ：
`^\top` `^\rho` `^\theta` `^\times` `^\bullet` `^\triangle` `^\textcirc` `^\text{deg}` `^\text{\circ}` `^\fr{circ}` `^\bc{^\text{o}}` `^\ngle` `^°` `^\u00b0`

- #207 以降の該当：#244, 243, 242, 241, 240, 236, 234, 232, 227, 226, 224, 223, 221, 220, 214, 212, 210, 208, 207（ほか #215〜219 は `^°` / `^\text{o}`）
- #207 以前の該当：#155〜#161 など
- **作成役 5 モデルすべてで発生**（gemma4:12b / e4b、qwen3.5:9b / 4b、bonsai-2）

**原因の仮説**：同じ問題でも **解説・ヒントでは `\circ` が正しく書けているケースが多い**（#242, 241, 240, 212 など）。モデル側の癖ではなく、**問題文生成時にコードから渡している条件文字列（例 `A = 120^\circ`）が壊れた状態でモデルに届いている**可能性が高い（例：`\c` が JSON の不正エスケープとして落ち `120^circ` になる等）。
→ **まず実際に送っているプロンプト文字列をログ出力して確認してほしい。**

## 5. 修正依頼

### A. 原因調査（最初にやる）
1. 問題文生成時に LLM へ送っているプロンプトの実文字列をログ出力し、角度・数式部分が壊れていないか確認
2. LLM 出力の JSON パース処理を確認（LaTeX のバックスラッシュが `\b` `\f` `\n` `\t` 等のエスケープとして解釈されていないか）

### B. 根本対策（推奨）
- 角度・辺の長さ・式などの **条件部分はコード側でテンプレート差し込み** にし、LLM には地の文（日本語）だけを書かせる
- 可能なら LLM 出力は構造化出力（JSON スキーマ）にし、数式フィールドはコード生成値を使う

### C. 後処理（正規化）
- `数字^` の直後の任意の記号（`\top` `\rho` `°` `\text{...}` `{...}` 等）を `^\circ` に統一
- `\\`（英字の前）を `\` に
- リテラル `\n` を改行に、`\u00b0` を `^\circ` に
- 制御文字（\x07 \x08 \x0c \t \r など）が含まれていたら再生成

### D. 機械的バリデーションを検証工程に追加（LLM 検証の前段）
不合格なら再生成 or 破棄：
1. KaTeX で全数式を `throwOnError: true` でパースして失敗を検出
2. 制御文字の検出
3. `$` の個数が偶数か、`\$` がないか
4. `$...$` 内に日本語（CJK 文字）がないか
5. 度記号が `^\circ` 以外になっていないか
6. 確率問題の選択肢が 0〜1 の範囲か、面積・長さの選択肢が正か
7. 選択肢の重複がないか、既存問題とのパラメータ重複がないか
8. 選択式の問題文に「示せ」「説明せよ」等が含まれていないか
9. CJK のうち中国語簡体字の混入検出（例：`边` `长` `计` `为` など）

### E. LLM 検証プロンプトへの追加
- 三角形の辺の対応（a=BC, b=CA, c=AB）が問題文と合っているか
- 解説の途中式が 1 行ずつ正しいか（最終答えだけでなく）
- 解説の言葉による説明（上側/下側、増加/減少など）が式と矛盾しないか

### F. 既存データ
- 1 章の ID は修正 or 再生成
- 2・3 章の該当は C の正規化を既存データにも一括適用し、D のバリデーションに再度かけて残ったものを再生成
